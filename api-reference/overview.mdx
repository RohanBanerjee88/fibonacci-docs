## Base URL and authentication

```
https://api.fibonacci.today/api/v1
```

Send `Authorization: Bearer <token>` with every request. The token is either a sign-in JWT or an **API key** (`fib_…`, created in the web app under Dashboard → Developer access, or with `POST /api-keys`). API keys carry **scopes**, such as `workflows:execute` or `agents:authorize`; `GET /api-keys/scopes` lists them.

```bash
curl https://api.fibonacci.today/api/v1/workflows \
  -H "Authorization: Bearer fib_..."
```

Interactive docs for a self-hosted API are at `/docs`.

## Responses and errors

Successful responses are the resource itself as JSON. Errors use FastAPI's shape:

```json
{"detail": "Jira rejected the login. Check JIRA_EMAIL is the Atlassian account the API token belongs to…"}
```

| Status | Meaning |
|---|---|
| `400` / `422` | The request isn't valid; `detail` says which field and why |
| `401` | Missing, expired or revoked token |
| `403` | Not allowed: your role, a missing API-key scope, or a governance rule that would deny the run |
| `404` | Doesn't exist, or isn't visible to you |
| `429` | Rate limit or org quota reached; honour `Retry-After` |
| `500` | An unexpected server error, still returned as JSON |

Rate limits are per client: 300 requests a minute by default, 10 a minute on login and 5 an hour on registration.

## Run a workflow

<Steps>
  <Step title="Generate it from a sentence (optional)">
    ```bash
    curl -X POST https://api.fibonacci.today/api/v1/workflows/generate \
      -H "Authorization: Bearer fib_..." -H "Content-Type: application/json" \
      -d '{"description": "Get issue 23 in the abc repo, write a fix.md, email it to xyz and set a 1:1 with them", "auto_save": true}'
    ```
    The response has the `workflow`, any `validation_errors`, the `required_inputs` (e.g. `xyz_email`) and `required_secrets` (e.g. `GITHUB_TOKEN`), and an `estimated_cost`.
  </Step>
  <Step title="Execute it">
    ```bash
    curl -X POST https://api.fibonacci.today/api/v1/workflows/{workflow_id}/execute \
      -H "Authorization: Bearer fib_..." -H "Content-Type: application/json" \
      -d '{"input_data": {"xyz_email": "xyz@acme.com"}}'
    ```
    Returns `202 Accepted` with the run. `status` is `pending` (queued for a worker), or `paused` with `approval_required: true` and an `approval_request_id` when governance holds it first. A run that a rule would definitely deny is refused with `403`; `detail.blocking` names each step, the rule and the labels involved.
  </Step>
  <Step title="Follow it">
    `GET /runs/{run_id}` for logs and node results, or stream the timeline as Server-Sent Events from `GET /runs/{run_id}/events`. `GET /runs/{run_id}/authorization` is the receipt: every tool call, its labels and the rule that decided it.
  </Step>
</Steps>

## Endpoints

All paths below are under `/api/v1`.

### Workflows

| Method | Path | |
|---|---|---|
| `POST` | `/workflows/generate` | Natural language → workflow (optionally save or execute) |
| `GET` · `POST` | `/workflows` | List · create |
| `GET` · `PATCH` · `DELETE` | `/workflows/{workflow_id}` | Read · update · delete |
| `POST` | `/workflows/{workflow_id}/execute` | Queue a run (`202`) |
| `POST` | `/workflows/{workflow_id}/authorization-preview` | What governance would decide for each step, without running |
| `GET` | `/workflows/{workflow_id}/runs` | Runs of one workflow |
| `GET` | `/workflows/{workflow_id}/stats`, `/stats` | Run statistics |

### Runs

| Method | Path | |
|---|---|---|
| `GET` | `/runs` | Your runs (personal and your orgs') |
| `GET` | `/runs/{run_id}` | Logs, node results, errors, and why a run hasn't started yet |
| `GET` | `/runs/{run_id}/events` | Live timeline (Server-Sent Events) |
| `GET` | `/runs/{run_id}/authorization` | The governance receipt |
| `POST` | `/runs/{run_id}/cancel` | Cancel a queued or running run |
| `POST` | `/runs/{run_id}/retry` | Retry a failed or cancelled run as a new run |

### Approvals

| Method | Path | |
|---|---|---|
| `GET` | `/approvals` | The inbox |
| `GET` | `/approvals/{approval_id}` | One request |
| `POST` | `/approvals/{approval_id}/approve` · `/reject` · `/cancel` | Decide (a paused run resumes on approve) |

### Governance

| Method | Path | |
|---|---|---|
| `GET` · `PATCH` | `/organizations/{org_id}/governance` | Settings |
| `GET` | `/governance/rule-templates` | Built-in rules to adopt |
| `GET` · `POST` | `/organizations/{org_id}/governance/rules` | List · create (or adopt a template) |
| `PATCH` · `DELETE` | `/organizations/{org_id}/governance/rules/{rule_id}` | Edit · remove |
| `GET` · `PATCH` | `/organizations/{org_id}/quota` | Limits and usage · overrides |
| `GET` · `PUT` · `DELETE` | `/organizations/{org_id}/tool-policies[/{tool_name}]` | Org tool policies |
| `GET` · `PUT` · `DELETE` | `/organizations/{org_id}/role-tool-policies[/{role}/{tool_name}]` | Per-role policies |
| `GET` | `/organizations/{org_id}/audit-events` | Audit log |
| `GET` | `/organizations/{org_id}/audit-events/verify` | Recompute the audit hash chain |
| `GET` | `/organizations/{org_id}/governance/summary`, `/approvals/report` | Reporting |

See [Governance](/guides/governance).

### External agents

| Method | Path | |
|---|---|---|
| `POST` | `/authorize` | Decide one agent tool call (scope `agents:authorize`) |
| `POST` | `/authorize/observe` | Report what a finished call read |
| `GET` | `/authorize/approvals/{approval_id}` | Poll an approval |
| `POST` | `/authorize/sessions/end` | Close a session |
| `GET` | `/agent-sessions` | Sessions in your orgs |
| `POST` | `/agent-sessions/{session_id}/revoke` | Kill switch |
| `GET` | `/integrations`, `/integrations/{name}` | Download the Claude Code hook and the MCP gateway (public) |

See [External agents](/guides/external-agents).

| Method | Path | |

See [Connect your tools](/getting-started/connect-your-tools).
