A tool node calls one of Fibonacci's built-in integrations. This page lists all of them, as the platform runs them today. `GET /api/v1/tools` (or `list_tools()` in the SDK) returns the same catalog with full JSON schemas.

## Using a tool node

<CodeGroup>

```python SDK
from fibonacci import ToolNode

read_issue = ToolNode(
    id="read_issue",
    name="Read the issue",
    tool="github_get_issue",
    params={"repo": "acme/api", "issue": "{{input.issue}}"},
)
```

```json Workflow JSON
{
  "id": "read_issue",
  "name": "Read the issue",
  "type": "tool",
  "tool_name": "github_get_issue",
  "tool_params": {"repo": "acme/api", "issue": "{{input.issue}}"},
  "dependencies": []
}
```

</CodeGroup>

### Passing data between steps

| Template | Resolves to |
|---|---|
| `{{input.name}}` | A workflow input |
| `{{node_id}}` | A previous step's whole output (cut to about 6,000 characters) |
| `{{node_id.field}}` | One field of a step's output, e.g. `{{create_channel.channel_id}}` or `{{read_issue.text}}` (not cut) |
| `{{today}}`, `{{yesterday}}`, `{{now}}` | The run's start date (`YYYY-MM-DD`) and time (ISO 8601, UTC), fixed for the whole run |

Templates work anywhere in `tool_params`, including inside lists and objects: `"attendees": ["{{input.email}}"]`.

<Tip>
  Tool outputs are objects. Pick the field you need (`{{create_channel.channel_id}}`): passing `{{create_channel}}` hands the whole JSON to a tool that expects an ID.
</Tip>

### Credentials

Tools that talk to a service read their credentials from the **Secrets Locker** of the person running the workflow (or from your organization's connection, for Slack). See [Connect your tools](/getting-started/connect-your-tools). A tool whose credentials are missing fails with a message that names the secret to add; nothing else in the workflow is affected unless a later step needs its output.

### Side effects

Every tool declares what it does to the world, and [governance](/guides/governance) keys off that, never off the tool's name:

- **read**: only fetches data
- **write**: changes something inside a connected system (a ticket, a card, a page, a channel)
- **egress**: delivers content to people or places outside the run (a message, an email, an invitation, a comment)

## Developer tools

Full guide: [Developer workflows](/guides/developer-workflows).

### GitHub

Needs `GITHUB_TOKEN`. Repositories can be `owner/name`, a link or just the name; issues and pull requests `23`, `#23`, `owner/name#23` or a link.

| Tool | Side effect | Parameters (* required) | Returns |
|---|---|---|---|
| `github_get_issue` | read | `issue`*, `repo`, `include_comments`, `max_comments` | `text`, `title`, `body`, `labels`, `assignees`, `comments`, `url`, `number`, `repo` |
| `github_list_issues` | read | `repo`*, `state`, `labels`, `assignee`, `query`, `limit` | `issues` (number, title, labels, assignees, url…) |
| `github_get_file` | read | `repo`*, `path`*, `ref` | `content`, `url` (or `entries` for a folder) |
| `github_search_code` | read | `repo`*, `query`*, `limit` | `results` (path, url, matches) |
| `github_list_commits` | read | `repo`*, `branch`, `since`, `until`, `path`, `author`, `limit` | `commits` (sha, title, message, author, date, url) |
| `github_list_pull_requests` | read | `repo`*, `state`, `limit` | `pull_requests` (…, `requested_reviewers`, `days_since_update`) |
| `github_get_checks` | read | `repo`*, `ref` | `state`, `summary`, `failed`, `pending`, `passed` |
| `github_get_pr` | read | `repo`*, `pr_number`* | `title`, `description`, `files` (with patches)… |
| `github_post_pr_review` | egress | `repo`*, `pr_number`*, `body`*, `event`, `comments` | `review_id`, `html_url` |
| `github_post_pr_comment` | egress | `repo`*, `pr_number`*, `body`* | `comment_id`, `html_url` |

### Jira (Cloud)

Needs `JIRA_BASE_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN`. Issues are a key (`OPS-7`) or a link. Descriptions and comments are Markdown. Your Jira credentials only ever go to `JIRA_BASE_URL`, over HTTPS: a link to another Jira site is refused, not followed.

| Tool | Side effect | Parameters (* required) | Returns |
|---|---|---|---|
| `jira_get_issue` | read | `issue`*, `include_comments` | `text`, `key`, `summary`, `status`, `assignee`, `description`, `comments`, `url` |
| `jira_search_issues` | read | `jql`, `project`, `query`, `status`, `assignee`, `limit` | `issues` |
| `jira_create_issue` | write | `project`*, `summary`*, `description`, `issue_type`, `assignee`, `labels`, `priority`, `due_date` | `key`, `url` |
| `jira_update_issue` | write | `issue`*, `status`, `assignee`, `summary`, `description`, `labels`, `priority`, `due_date` | `key`, `changed`, `status`, `url` |
| `jira_add_comment` | egress | `issue`*, `comment`*, `attachment_name`, `attachment_content` | `comment_id`, `attachment_url` |

`assignee` takes `me`, an email or a display name; `status` moves the issue through the transition that leads there.

### Trello

Needs `TRELLO_API_KEY`, `TRELLO_TOKEN`. Boards by name, link or ID; lists by name; cards by link, ID, or by name together with `board`.

| Tool | Side effect | Parameters (* required) | Returns |
|---|---|---|---|
| `trello_get_board` | read | `board`* | `lists` (each with its `cards`), `card_count`, `url` |
| `trello_search_cards` | read | `query`*, `board`, `limit` | `cards` (name, url, list, board, due…) |
| `trello_create_card` | write | `board`*, `list`*, `name`*, `description`, `due`, `members`, `labels`, `position` | `id`, `url` |
| `trello_update_card` | write | `card`*, `board`, `list`, `name`, `description`, `due`, `due_complete`, `members`, `labels`, `archive` | `url`, `list`, `changed` |
| `trello_add_comment` | egress | `card`*, `text`*, `board`, `attachment_name`, `attachment_content` | `comment_id`, `attachment_url` |

## Google Workspace

Sign in with Google (Settings → Integrations); runs use your Google login.

| Tool | Side effect | Parameters (* required) | Returns |
|---|---|---|---|
| `google_docs_read` | read | `document_id`* | the document's text |
| `google_sheets_read` | read | `spreadsheet_id`*, `range_name` | rows |
| `gmail_send` | egress | `to`*, `subject`*, `body`*, `cc`, `bcc`, `attachment_name`, `attachment_content` | `message_id`, `attachment` |
| `google_calendar_create_event` | egress | `summary`*, `start_time`, `end_time`, `attendees`, `description`, `duration_minutes`, `time_zone`, `add_meet_link` | `event_id`, `link`, `meet_link`, `start_time`, `end_time` |
| `google_drive_permissions` | egress | `file_id`*, `email`*, `role` | `permission_id` |

- `gmail_send` with `to: "me"` sends to whoever ran the workflow. `attachment_name` + `attachment_content` attach a text file, such as a generated `fix.md`.
- `google_calendar_create_event` without `start_time` books the next business day at 10:00 in your calendar's time zone; without `end_time`, it lasts `duration_minutes` (30). `add_meet_link: true` adds Google Meet. Attendees get Google's invitation email.
- Google Sheets and Docs IDs can be pasted as full links in [governance rules](/guides/governance#label-rules).

<CodeGroup>

```python Email a generated file
send = ToolNode(
    id="send_fix",
    name="Send fix.md",
    tool="gmail_send",
    params={
        "to": "{{input.reviewer_email}}",
        "subject": "Fix plan: {{read_issue.title}}",
        "body": "Plan attached.",
        "attachment_name": "fix.md",
        "attachment_content": "{{write_fix}}",
    },
    dependencies=["write_fix"],
)
```

```python Book a 1:1
meeting = ToolNode(
    id="one_on_one",
    name="1:1",
    tool="google_calendar_create_event",
    params={
        "summary": "1:1: {{read_issue.title}}",
        "attendees": ["{{input.reviewer_email}}"],
        "add_meet_link": True,
    },
)
```

</CodeGroup>

## Messaging

### Slack

An org admin can connect the workspace once (**Organization → Integrations → Add to Slack**); runs in that org then post as the Fibonacci bot. Otherwise a member's `SLACK_BOT_TOKEN` is used.

| Tool | Side effect | Parameters (* required) | Returns |
|---|---|---|---|
| `slack_send_message` | egress | `channel`*, `text`*, `thread_ts` | message details |
| `slack_create_channel` | write | `name`*, `is_private`, `description`, `invite` | `channel_id`, `channel_name` |
| `slack_upload_file` | egress | `channel`*, `file_path`*, `title`, `initial_comment` | file details |

- `channel: "@me"` (or a person's email) is a **direct message**, which is what reaches a phone.
- `slack_create_channel` invites the person who ran the workflow, plus anyone in `invite` (emails or member IDs). Someone who can't be invited shows as a warning in the run log; the channel is still created.
- Errors such as `channel_not_found` name the workspace the bot is in and how to `/invite` it.

### Discord

Needs `DISCORD_BOT_TOKEN` and `DISCORD_GUILD_ID` (and `DISCORD_USER_ID` for `@me`). Setup: **Organization → Integrations → Discord**.

| Tool | Side effect | Parameters (* required) | Returns |
|---|---|---|---|
| `discord_send_message` | egress | `channel`* (ID, `#name` or `@me`), `content`* | `channel_id`, `message_ids` |
| `discord_create_channel` | write | `name`*, `topic`, `category` | `channel_id`, `channel_name`, `url` |

Channels go under one "Fibonacci" category and are reused if they exist. Long messages are split at 2,000 characters, and mentions never ping.

| Tool | Side effect | Needs | Parameters (* required) |
|---|---|---|---|

## Built in (no credentials)

| Tool | Side effect | Parameters (* required) | Notes |
|---|---|---|---|
| `web_search` | read | `query`*, `num_results` | Live web search. Returns a short answer and the source URLs. Slow and paid per call: one subject per search, `num_results: 1` for a single fact. Never use it for today's date, which is `{{today}}`. Output is labelled `untrusted`. |
| `text_analysis` | read | `text`*, `analysis_type` | Sentiment, key points, entities, themes |
| `text_processor` | read | `text`*, `operation`, `params` | Extract lines, count words, clean whitespace… |
| `file_reader` | read | `file_path`*, `encoding`, `file_type` | Reads text, CSV or JSON files from the server's sandboxed files folder (`FILE_READER_BASE_DIR`); nothing outside it |

Files you attach when you run a workflow (PDF, Word, Excel, CSV) don't need a tool: their text reaches LLM steps as `{{input.uploaded_files}}`.

## Timeouts and retries

- Each call gets the node's `config.timeout`, or the tool's default: 30 seconds, and 90 for `web_search`.
- A failed call is retried up to `config.max_retries` (3) times with a growing delay, **unless retrying can't help**: a bad or missing credential, a missing permission, something that doesn't exist, or an input that isn't valid. Those fail once, with a message that says what to change.
- Mark steps whose failure shouldn't stop the run with `"config": {"continue_on_error": true}`, typically notifications:

```python
notify = ToolNode(
    id="notify",
    name="Tell me",
    tool="slack_send_message",
    params={"channel": "@me", "text": "{{summary}}"},
).with_retry(max_retries=2, delay=2.0)
```
